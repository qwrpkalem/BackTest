# 버전별 아카이브

백테스트를 실행한 각 버전에 대해 **그때 사용한 스펙 문서**와 **그 결과 리포트**를
한 쌍으로 보관합니다. 스펙만 있으면 결과를 알 수 없고, 리포트만 있으면 어떤 조건에서
나온 숫자인지 알 수 없기 때문에 반드시 함께 남깁니다.

```
output/history/
  v1/  spec.md  report.md
  v2/  spec.md  report.md
```

| 버전 | 날짜 | 핵심 조건 | 결과 | 문서 |
|---|---|---|---|---|
| **v1** | 2026-08-03 | 52주 신고가 + ATR + 거래대금 2.5배<br>유니버스: **시총 1조 이상** (월평균 214종목) | CAGR **+3.83%**<br>MDD -42.01% | [스펙](v1/spec.md) · [리포트](v1/report.md) |
| **v2** | 2026-08-04 | v1 + **RS(상대강도) 조건**<br>유니버스: **시총 필터 제거** (월평균 1,905종목) | CAGR **-18.78%**<br>MDD -92.55% | [스펙](v2/spec.md) · [리포트](v2/report.md) |
| **v3** | 2026-08-05 | v2의 RS 유지 + **시총 1조 필터 복원**<br>= 사실상 "v1 + RS" | CAGR **+4.32%**<br>MDD -39.27% | [스펙](v3/spec.md) · [리포트](v3/report.md) |
| **v4** | 2026-08-05 | v3와 진입조건 동일<br>**사이징만 R 기반 가변**(2R~6R) | CAGR +1.95%<br>MDD -43.89% | [스펙](v4/spec.md) · [리포트](v4/report.md) |
| **v5** | 2026-08-05 | v4의 R 범위를 절반으로<br>(1R~3R = 자산의 4.17~12.5%) | CAGR +3.55%<br>MDD **-27.92%** | [스펙](v5/spec.md) · [리포트](v5/report.md) |

> **v1↔v3** 비교 = RS 조건 단독의 순효과 (유니버스 동일).
> CAGR +0.49%p, MDD 2.74%p 개선 — 방향은 맞지만 폭이 작습니다.
>
> **v3↔v4↔v5** 비교 = 포지션 사이징 방식의 순효과 (진입·청산 조건, 매매 목록 동일).
> v4는 베팅이 커져 악화(현금부족 23.9%), v5는 절반으로 줄여 MDD 11.35%p 개선.
>
> ⚠️ 단 **대조군 검증** 결과, v5의 개선은 R 배분 로직이 아니라 **평균 베팅 축소** 때문입니다.
> R 변동을 없애고 같은 평균 노출(7.594%)로 고정하면 CAGR +3.29% / MDD -24.43% 로,
> 위험조정 수익(CAGR/|MDD|)이 오히려 더 높습니다 (0.135 vs 0.127).
>
> **절대 수익은 v3(+4.32%), 위험조정은 v5·대조군이 우수**합니다. 목적에 따라 선택이 갈립니다.

변경 이유와 원인 분석은 [../CHANGELOG.md](../CHANGELOG.md)를 참고하세요.

## 새 버전 아카이브 방법

백테스트를 돌린 **직후**(스펙을 다시 수정하기 전에) 아래를 실행하면 됩니다.

```bash
python src/archive_version.py v3 "설명"
```

`backtest_spec.md`와 `output/report.md`를 `output/history/v3/`에 함께 복사합니다.

> ⚠️ v1 스펙은 이 규칙이 없던 시절에 v2로 덮어써져 원본이 유실됐고, 세션 기록에서
> 복원한 사본입니다([v1/spec.md](v1/spec.md) 상단 주석 참고). 같은 일이 반복되지
> 않도록 위 스크립트를 쓰세요.
